🔴 **미러를 고치면 안 되는 이유**: 팀 최신본을 다시 받을 때 쓰는 `git push --mirror` 는
원본에 없는 ref·파일을 **전부 지운다.** 미러에 수정을 얹으면 다음 갱신 때 통째로 날아간다.
그래서 고치는 곳을 물리적으로 분리했다.

미러 갱신이 필요하면:
```bash
git clone --bare https://github.com/pmhllll12/super-sub.cloud.git /tmp/ss.git
git -C /tmp/ss.git push --mirror https://github.com/paiksunggum/super-sub.cloud.git
```
⛔ 이 명령을 **이 저장소나 팀 저장소로 쏘지 말 것.** 원격을 로컬 상태로 덮어쓴다.

🔴 **팀 원본과 다른 파일은 아래뿐**이다. 팀 최신본을 다시 받을 때 **이것만 빼고 덮으면 된다.**

## 4. 「내 역할」 페이지 — 지금 구성

```
백성검 · 한 줄 소개 · 연락처(GitHub · 이메일 · 데모)

```

### 🔴 글을 고칠 때 지킬 것 — 여러 번 되돌린 끝에 정한 것들

1. **설명 못 할 말은 쓰지 않는다.** 면접에서 물으면 바로 무너지고, 그건 안 쓴 것보다 나쁘다.
   그래서 `watch`/`invalidate` · `jsdom` · 딥링크 · 리포지토리 같은 말을 전부 쉬운 말로 바꿨다.
   ⛔ 「전역 상태 관리 시 불필요한 위젯 리렌더링을 방지하고 컴파일 타임 안전성을 확보하기 위해」
   같은 문장으로 되돌리지 말 것 — 어느 포트폴리오에나 붙는 말이고 본인이 설명 못 한다.
2. ⛔ **「Clean Architecture」로 적지 않는다.** 이 앱은 기능으로 먼저 나누고 그 안을 셋으로
   나눈 **Feature-first** 다. Clean Architecture 라고 적으면 의존성 역전·UseCase 를 되묻는다.
3. ⛔ **Provider·Bloc·GetX 와의 비교를 적지 않는다.** 실제로 견준 적이 없다.
   라벨도 「대신 생각한 것」(= 내가 견줬다)이 아니라 **「이 방법이 아니었다면」**(= 그 방법의 성질)이다.
4. ⛔ **Dio 를 적지 않는다.** 이 앱은 `http` 패키지를 쓴다(`lib/core/network/api_client.dart`).
5. ⛔ **코드 줄 수·커밋 수를 적지 않는다.** 줄 수는 장황함으로, 커밋 수는 습관 차이로 읽힌다.
6. ⛔ **전화번호를 적지 않는다.** 공개 사이트라 크롤러가 긁어가고 되돌릴 수 없다.
7. 🔴 **기간은 5주다.** 10주는 팀 프로젝트 **계획** 기간이고, 백성검의 실제 작업은
   2026-08-24 ~ 09-29 = **36일 = 5주 1일**이다(git 으로 잼).
8. **수치는 저장소에서 센 값만 쓴다.** 994 는 `flutter test` 를 직접 돌려 확인했다
   (위젯 311 · 단위 568, 전부 통과).

## 5. 🔴 CSS 를 고칠 때 밟았던 함정들 — 다시 밟지 말 것

| 증상 | 원인 |
|---|---|
| 인라인 스크립트가 **조용히 안 돈다** | 이 사이트는 HTML 을 **한 줄로 압축**한다. `//` 줄 주석이 뒤 코드를 통째로 삼킨다 → 주석은 `/* */` |
| 사이드바 폭을 줄였는데 **본문이 겹친다** | 테마가 `width` 외에 **`min-width`** 도 건다. 둘 다 덮어야 한다 |
| 사이드바를 줄였는데 **HOME 이 안 가운데, 선이 넘친다** | `.site-header` · `.site-nav` 에 테마 기본 폭이 따로 박혀 있다 → `width: 100%` |
| 글자 크기가 **안 먹는다** | 테마의 `fs-*` 믹스인이 `font-size: … !important` 다 |
| 가름선이 칸 **안쪽에서 끝난다** | 좌우 여백을 칸이 아니라 **줄**이 가져야 한다. 선은 줄의 테두리다 |
| 격자인데 **줄이 글자 너비만큼만** | 앞서 넣은 `justify-content: center` 가 격자에서 트랙을 가운데로 모은다 |
| 제목 두 줄이 **특정 폭에서만 접힌다** | `vw`(화면)가 아니라 **`cqw`(글 칸)** 를 기준으로 재야 한다. 오른쪽 사진 기둥이 자리를 먹는다 |
| 머리칸 제목이 **화면 가운데가 아니다** | 머리칸은 `.main` 안에 있다. 사이드바 폭만큼 당겨야 하고 **구간마다 그 폭이 다르다**(14rem / 15.5rem) |
| HOME 에 마우스를 올리면 **흰색으로 사라진다** | `background-clip: text` 를 쓰면 테마의 hover 배경이 글자를 덮는다 → 쓰지 말 것 |
| 다크 값을 재는데 **라이트가 나온다** | 검사 전에 `localStorage.clear()` — 앞 회차의 테마 선택이 남는다 |

## 6. 확인하는 법

```bash
export PATH="$HOME/.rbenv/bin:$PATH"; eval "$(rbenv init - bash)"
bundle exec jekyll build --source . --destination ./_site
```

🔴 **눈으로만 보지 말 것.** 이 사이트는 헤드리스 크롬으로 **좌표를 재서** 확인해 왔다.
(스크린샷도 되지만 레이아웃 결함은 숫자로 봐야 잡힌다.)

로컬 서버 + 크롬을 띄우고 CDP 로 재는 방식이다. 쓰던 검사 네 벌:
- 표지 기둥 앱/웹 전환과 화면 고르기
- 사이드바 묶음 접기·펴기
- 앱 화면이 잘리지 않고 전부 보이는지
- 폭별 배치(기둥 고정/해제, 가로 넘침)

🔴 **글자가 몇 줄인지 셀 때는 `Range.getClientRects()` 를 쓸 것.**
`display:block` 인 요소의 `getClientRects()` 는 글자가 접혀도 1을 돌려준다 —
이것 때문에 「두 줄」을 통과시켜 놓고 실제로는 세 줄이던 적이 있다.
