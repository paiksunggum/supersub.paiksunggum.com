# RFP 기반 개발 실행 하네스

> **사업명** 생활체육 경기 영상을 멀티모달로 분석하여 용병을 구인하고 RAG 검증을 자동화하는 플랫폼
> **팀명** Super-Sub / 슈퍼서브
> **기간** 2026-08-20 ~ 2026-10-27 (10주, 5스프린트)
> **인원** 백성검(PM·앱) · 박민호(파이프라인) · 정상호(에이전트) · 정어진(백엔드·웹)

---

## 1. 목적과 적용 범위

본 문서는 Claude Code가 이 사업의 코드·테스트·설정을 생성할 때 **요구사항의 명확성·원자성·
추적성·검증성**을 보장하기 위한 실행 규칙이다. 제안서 본문(`ch01`~`ch09`)이 "무엇을 왜
만드는가"를 정의한다면, 이 문서는 **"그것을 어떤 규격으로 구현하고 어떻게 검증하는가"**를
정의한다.

### 적용 범위

| 대상 | 적용 |
|---|---|
| 애플리케이션 코드 (앱·웹·API·분석·에이전트) | **적용한다** |
| 테스트·설정·인프라 정의 | **적용한다** |
| 제안서 문서 사이트(Jekyll) 자체 | 적용하지 않는다. `CLAUDE.md`를 따른다 |

> **확인 필요** — 현재 저장소는 제안서 문서 사이트다. 애플리케이션 코드는 **별도 저장소**를
> 두는 것을 권장한다. 같은 저장소에 두면 Jekyll 빌드 대상에서 코드 디렉터리를 매번 제외해야
> 하고, 문서 배포와 앱 배포가 한 파이프라인에 섞인다. 팀 협의 후 확정한다.

## 2. 필수 준수 규칙

### 2.1 명확성 — 모호한 표현을 남기지 않는다

측정 불가능한 서술을 요구사항이나 주석에 쓰지 않는다.

| 금지 | 대체 |
|---|---|
| "영상을 빠르게 분석한다" | "30초 클립 기준 분석 완료까지 90초 이내" |
| "정확하게 추천한다" | "평가 데이터셋 기준 Recall@5 90% 이상" |
| "적절한 영상만 받는다" | "인물 1명·전신 포함·5~30초·720p 미만은 업로드 반려" |

### 2.2 원자성 — 요구사항 ID 단위로 독립 검증

하나의 요구 ID는 하나의 검증 가능한 단위다. 복합 기능은 ID를 분리한다.
ID를 걸치는 모듈은 만들지 않는다.

### 2.3 추적성 — 모든 산출물에 요구 ID를 명시

생성하는 모든 소스·테스트·설정 파일 상단에 관련 요구 ID를 주석으로 남긴다.

```python
# Requirement ID: SFR-002 (자세 추정 및 지표 산출)
# Related: QUA-002 (재현성), 제안서 3.3 분석 파이프라인
```

```dart
// Requirement ID: SFR-001 (영상 업로드 및 규격 사전 검사)
```

```typescript
// Requirement ID: SFR-009 (카드 공개 페이지)
```

### 2.4 검증성 — 검수 기준과 테스트를 함께 생성

기능 코드만 생성하지 않는다. 해당 요구 ID의 검수 기준을 확인하는 테스트를 같은 작업에서
작성한다. 테스트 없는 구현은 완료로 보지 않는다(7.4 DoD).

### 2.5 설계 원칙 준수 — 제안서와 어긋나는 구현을 만들지 않는다

다음은 제안서에서 확정한 설계 원칙이다. 코드가 이를 위반하면 요구사항 충족 여부와 무관하게
반려한다.

| 원칙 | 출처 | 금지되는 구현 |
|---|---|---|
| 지표 산출은 규칙 기반, 재현 가능해야 한다 | 3.3 | LLM에게 자세 지표 수치를 생성하게 하는 구현 |
| 매칭 확정은 사람이 한다 | 3.3 | 에이전트가 자동으로 매칭을 확정하는 구현 |
| 추천에는 근거를 함께 제시한다 | 3.3 | 점수만 반환하고 사유가 없는 추천 API |
| 전체 순위표를 두지 않는다 | 3.4 | 사용자 정렬·랭킹·카드 대결 기능 |
| 카드에 수치 능력치를 노출하지 않는다 | 3.5 | 카드 응답에 능력치 점수를 포함하는 API |
| 부정 평가는 호칭 미부여로만 작동한다 | 3.5 | 평가로 등급·호칭을 차감하는 로직 |
| 분석 입력은 단일 인물 5~30초 클립 | 3.2 | 다중 인물 추적·경기 전체 영상 분석 |

## 3. 시스템 아키텍처와 R&R

```
[ 클라이언트 ]                    [ AWS ]

Flutter 앱 ──┐                  FastAPI (API 서버)
             ├──── HTTPS ────→   ├── 인증 · 매칭 · 평가
Next.js 웹 ──┘                   ├── 적합도 산출 (pgvector 유사도)
  (공개 카드·스쿼드)              └── 에이전트 호출 (Claude API)
                                       │
                                 분석 워커 (Docker, Python)
                                 자세 추정 → 지표 산출 → JSON
                                       │
                                 Aurora PostgreSQL + pgvector
                                 S3 (업로드 영상)
```

### 담당과 디렉터리

| 담당 | 영역 | 디렉터리 | 요구 ID |
|---|---|---|---|
| **백성검** | PM · Flutter 앱 | `apps/app` | SFR-001, 003, 008, 010 |
| **정어진** | 백엔드 · 웹 | `services/api`, `apps/web` | SFR-005, 006, 009, 010, SEC 전체 |
| **박민호** | 영상 분석 파이프라인 | `services/analysis` | SFR-002, PER-001 |
| **정상호** | AI 에이전트 · RAG | `services/agent` | SFR-003, 007, PER-002 |

경계에서 주고받는 형식(지표 JSON, API 규격)은 **스프린트 1에 먼저 고정한다**(7.3).

## 4. 요구사항 명세

### 4.1 기능 요구사항 (SFR)

| 요구 ID | 기능 | 정의 | 코드 위치 | 검수 기준 |
|---|---|---|---|---|
| **SFR-001** | 영상 업로드·규격 검사 (F-01, F-01a) | 클립 업로드 후 인물 수·크기·길이·흔들림을 검사해 미달분을 반려한다 | `apps/app`, `services/api/routers/upload.py` | 인물 2명 이상·전신 미포함·길이 초과 영상이 **100% 반려**되고 반려 사유가 반환된다 |
| **SFR-002** | 자세 추정·지표 산출 (F-02) | 동작 구간을 검출하고 관절 좌표에서 종목별 자세 지표를 **규칙 기반**으로 계산한다 | `services/analysis/pose.py`, `metrics.py` | 동일 영상 3회 분석 시 지표값이 **완전히 동일**하다(QUA-002) |
| **SFR-003** | 분석 리포트·특징 요약 (F-03) | 수치 지표를 근거로 플레이 성향 요약 문장을 생성한다 | `services/agent/summarize.py` | 생성 문장에 **입력 지표에 없는 수치가 등장하지 않는다** |
| **SFR-004** | 호칭 부여 (F-13) | 절대 기준 충족 여부로 강점·활동·용병 호칭을 부여한다 | `services/api/services/titles.py` | 표본 미달 시 "확인 중"을 반환하고, **기준 미달이 부정 표식으로 표시되지 않는다** |
| **SFR-005** | 벡터 색인·유사도 검색 | 특징 벡터를 pgvector에 저장하고 유사도로 후보를 조회한다 | `services/api/repositories/vector.py` | 저장 후 조회 시 **본인 벡터가 1순위로 반환**된다 |
| **SFR-006** | 적합도 산출 (F-04) | 수준·역할·성향 3축으로 적합도를 계산한다 | `services/api/services/fitness.py` | 축별 부합·이탈 여부가 **개별 필드로 반환**된다 |
| **SFR-007** | 후보 추천·근거 생성 (F-05) | 적합도 상위 후보를 순위와 **추천 사유**와 함께 제시한다 | `services/agent/recommend.py` | 모든 추천 항목에 사유 문자열이 존재하고, 사유가 **조회된 지표에서만 인용**된다 |
| **SFR-008** | 상호 평가·신뢰도 (F-09, F-15) | 경기 후 상호 평가를 받고 평가자 신뢰도를 가중치에 반영한다 | `services/api/routers/review.py` | **양측 제출 전 상대 평가가 조회되지 않는다**(블라인드) |
| **SFR-009** | 카드 공개 페이지 | 앱 설치 없이 링크로 카드·스쿼드를 열람한다 | `apps/web/app/card/[id]/page.tsx` | 비로그인 상태에서 **200 응답 및 OG 태그가 생성**된다 |
| **SFR-010** | 경기 등록·매칭 처리 (F-06, F-07) | 경기를 등록하고 지원·제안·수락을 처리한다 | `services/api/routers/match.py` | **양측 수락 전에는 매칭이 확정되지 않는다** |

### 4.2 성능 요구사항 (PER)

| 요구 ID | 정의 | 코드 위치 | 검수 기준 |
|---|---|---|---|
| **PER-001** | 분석 처리 시간 — 업로드 응답과 분석을 분리한다 | `services/analysis/worker.py` | 30초 클립 기준 분석 완료 **90초 이내**, 업로드 API는 **1초 이내** 응답 |
| **PER-002** | 추천 정확도 — 평가 데이터셋 기준 | `services/agent/eval/` | **Recall@5 90% 이상, Hit Rate 90% 이상** |
| **PER-003** | 조회 응답 — 카드·리포트 조회 | `services/api` | 정상 부하에서 **P95 500ms 이내** |

> **확인 필요** — PER-002의 90%는 제안서 제목에 표기된 **목표치**다. 평가 데이터셋(정답
> 매칭 쌍)의 구성 방법과 산출식을 8장에서 먼저 정의해야 측정할 수 있다. 데이터셋 정의 전에는
> 달성 여부를 주장하지 않는다.

### 4.3 보안 요구사항 (SEC)

| 요구 ID | 정의 | 코드 위치 | 검수 기준 |
|---|---|---|---|
| **SEC-001** | 자격 증명 비노출 | `.env`, `.env.local` | 저장소에 실제 키·접속 정보가 **커밋되지 않는다.** `NEXT_PUBLIC_`에 비밀값이 없다 |
| **SEC-002** | 업로드 영상 접근 제어 | `services/api/storage.py` | 영상은 **서명 URL로만 접근**되며 만료 후 403이 반환된다 |
| **SEC-003** | 인증·인가 | `services/api/middleware/` | 미인증 요청은 **401**, 타인 리소스 요청은 **403**을 반환한다 |
| **SEC-004** | CORS | `services/api/main.py` | 허용 오리진(앱·웹) 외 요청이 차단된다 |
| **SEC-005** | AWS 계정 운용 | 인프라 | **루트 계정을 사용하지 않는다.** IAM 사용자·역할로만 접근한다 |
| **SEC-006** | 개인 영상 보호 | 전체 | 타인이 등장하는 영상을 받지 않는다(입력 규격). 삭제 요청 시 원본·파생물이 함께 삭제된다 |

### 4.4 품질 요구사항 (QUA)

| 요구 ID | 정의 | 코드 위치 | 검수 기준 |
|---|---|---|---|
| **QUA-001** | 자동화 테스트 | `tests/` | 핵심 로직(분석·적합도·호칭·인증) **커버리지 80% 이상** |
| **QUA-002** | 재현성 | `tests/test_metrics_repeat.py` | 동일 입력에 대해 지표가 항상 동일하다. **LLM 출력이 지표 계산에 개입하지 않는다** |
| **QUA-003** | 생성 문장 검증 | `tests/test_agent_grounding.py` | 요약·추천 사유에 **입력에 없는 수치·사실이 포함되지 않는다** |
| **QUA-004** | 설계 원칙 준수 | `tests/test_design_rules.py` | 카드 응답에 수치 능력치가 없고, 정렬·랭킹 엔드포인트가 존재하지 않는다 |

## 5. 실행 태스크

### Task 1 — 모노레포 뼈대 구축

```
RFP 하네스(.claude/rules/rfp-harness.md)를 반영해 프로젝트 뼈대를 구축한다.
1. 워크스페이스 구성: apps/app(Flutter), apps/web(Next.js), services/api(FastAPI),
   services/analysis(Python 워커), services/agent(Python)
2. apps/web: Next.js App Router + TypeScript. 로컬에서 /api를 localhost:8000으로 프록시
3. services/api: FastAPI 기본 앱 + CORS 미들웨어 (SEC-004)
4. .env.example / .env.local.example 기준으로 설정 로딩 (SEC-001)
5. 생성하는 모든 파일 상단에 관련 요구 ID 주석을 명시
```

### Task 2 — SFR-002 분석 파이프라인

```
SFR-002에 따라 services/analysis에 자세 추정·지표 산출 모듈을 구현한다.
- 입력: 단일 인물 5~30초 클립. 규격 미달 시 예외를 발생시킨다(SFR-001 연계)
- 처리: 동작 구간 검출 → 관절 좌표 추정 → 종목별 지표 계산(규칙 기반)
- 출력: 스프린트 1에서 확정한 지표 JSON 규격
- 함께 생성: 동일 영상 3회 분석 결과가 일치하는지 검증하는 테스트 (QUA-002)
- LLM을 지표 계산에 사용하지 않는다
```

### Task 3 — SFR-006·007 적합도와 추천

```
SFR-006, SFR-007을 구현한다.
- services/api/services/fitness.py: 수준·역할·성향 3축 적합도. 축별 결과를 개별 반환
- 성향 축은 pgvector 유사도를 사용한다 (SFR-005)
- services/agent/recommend.py: 상위 후보에 대한 추천 사유 생성.
  조회된 지표만 근거로 사용하고, 없는 수치를 만들어내지 않는다
- 함께 생성: 추천 응답에 사유가 누락되지 않는지, 사유에 미존재 수치가 없는지 검증 (QUA-003)
- 매칭 확정은 이 단계에서 수행하지 않는다
```

## 6. 추적성 검증 체크리스트

작업 완료 시 아래를 순서대로 확인한다.

- [ ] **추적성** — 생성된 모든 소스·테스트 파일 상단에 `Requirement ID:` 주석이 있는가
- [ ] **테스트 동반** — 이번에 구현한 요구 ID마다 검수 기준을 확인하는 테스트가 있는가
- [ ] **재현성** — 동일 입력에 지표가 동일하게 산출되는가 (QUA-002)
- [ ] **근거성** — 생성 문장에 입력에 없는 수치가 섞이지 않았는가 (QUA-003)
- [ ] **설계 원칙** — 2.5의 금지 구현이 포함되지 않았는가 (QUA-004)
- [ ] **보안** — 실제 키·접속 정보가 코드나 문서에 포함되지 않았는가 (SEC-001)
- [ ] **연동** — 웹(3000) → API(8000) 호출이 CORS 설정 하에서 동작하는가 (SEC-004)
- [ ] **설정 문서화** — 새로 필요한 환경 변수가 `.env.example`에 반영되었는가
- [ ] **미달성 표기** — 측정하지 않은 성능 수치를 달성한 것처럼 서술하지 않았는가

| 접두사 | 영역 | 부여 시점 |
