# 자동 메모리 동작 방식

> 짝 문서: [[memory-layout]] — 메모리가 **어디에** 저장되고 어떤 규약을 따르는지 다룬다.
> 이 문서는 저장된 메모리가 **언제 어떻게 읽히는지**를 다룬다.

## 200줄 규칙

세션이 시작될 때 시스템 프롬프트에 자동으로 들어가는 것은 **`MEMORY.md`의 첫 200줄**이다.

| 대상 | 자동 로드 | 제한 |
|------|-----------|------|
| `MEMORY.md` | ✅ 세션 시작 시 | **첫 200줄까지** |
| `MEMORY.md`의 201줄 이후 | ❌ | 필요할 때 읽어감 |
| 개별 주제 파일 (`project_*.md` 등) | ❌ | 없음 |
| `CLAUDE.md` | ✅ **전체** | 없음 (단, 권장치 있음 — 아래 참고) |

**200줄 제한은 `MEMORY.md`에만 적용된다.** 개별 메모리 파일은 길이 제한이 없고, 대신 시작 시 로드되지 않는다. 인덱스의 한 줄 요약을 보고 필요하다고 판단했을 때만 열어서 읽는다.

그래서 구조가 이렇게 갈린다.

```
MEMORY.md          ← 짧게. 200줄 안에서 전체를 훑을 수 있어야 함
  └─ 각 줄이 포인터
project_xxx.md     ← 길어도 됨. 상세 맥락·재현 절차·함정 전부
```

### 이 구조가 주는 실무 지침

**인덱스의 한 줄 요약(hook)이 전부다.** 그 한 줄만 보고 "지금 이 파일을 열어야 하는가"를 판단하기 때문에, 요약이 막연하면 상세 파일은 영영 열리지 않는다.

```markdown
❌ - [배포](project_ec2_migration.md) — 배포 관련 메모
✅ - [백엔드 EC2 이전 완료](project_ec2_migration.md) — Elastic IP 3.35.114.50 고정,
     EC2가 유일한 프로덕션, 배포는 이미지 push 후 `docker compose pull`. `ssh aws`
```

상세는 파일에 넣고, 인덱스에는 **판단에 필요한 최소 단서**를 남긴다.

## CLAUDE.md는 전체가 로드된다

`CLAUDE.md`에는 200줄 제한이 걸리지 않는다. 길이와 무관하게 전부 읽힌다.
다만 **200줄 이내로 유지하면 지시사항 준수율이 올라간다.** 길수록 개별 지시의 밀도가 낮아지기 때문이다.

### 현재 이 프로젝트 실측 (2026-07-29 기준)

| 파일 | 줄 수 | 상태 |
|------|-------|------|
| `MEMORY.md` | 15 / 200 | ✅ 여유 충분 |
| 개별 메모리 13개 | 합계 513 (최대 127) | ✅ 제한 없음, 온디맨드 |
| **`CLAUDE.md`** | **380** | ⚠️ **권장치의 약 1.9배** |

`CLAUDE.md`가 380줄까지 늘어난 상태다. 당장 동작에 문제는 없지만(전체 로드됨), 준수율 관점에서는 분리 대상이다. 줄이는 방향은 **삭제가 아니라 이관**이다.

- 경로 한정 규칙 → `.claude/rules/*.md` (`paths:` 프론트매터로 해당 파일 편집 시에만 로드)
- 도메인별 상세 → 각 앱의 `_docs/`
- `CLAUDE.md`에는 **항상 필요한 것만** 남긴다

## 활성화 / 비활성화

자동 메모리는 **기본 활성**이다. 끄는 방법은 세 가지다.

**1. 환경변수**
```bash
export CLAUDE_CODE_DISABLE_AUTO_MEMORY=1
```

**2. `settings.json`**
```json
{
  "autoMemoryEnabled": false
}
```

**3. `/memory` 명령어의 토글**

되돌리려면 환경변수를 제거하거나 `autoMemoryEnabled`를 `true`로 되돌린다.

### 현재 상태 (2026-07-29 확인)

```
CLAUDE_CODE_DISABLE_AUTO_MEMORY  → 미설정
settings.json의 autoMemoryEnabled → 미설정
```

둘 다 없으므로 **기본값인 활성 상태로 동작 중**이다. 이 프로젝트에서 끌 이유는 없다.
여러 컴퓨터를 오가며 작업하는 구조라, 이전 환경에서 확정한 맥락을 다음 세션이 이어받는 것이 이 설정의 핵심 이득이다.

## 서브에이전트 자동 메모리

서브에이전트도 **자체 자동 메모리를 독립적으로** 가질 수 있다. 커스텀 서브에이전트 정의에서 활성화하면 각 에이전트가 자기 메모리를 따로 쌓는다.

메인 세션과 메모리가 **공유되지 않고 분리된다는 점**이 핵심이다. 특정 역할(예: 배포 점검, 리뷰)을 반복 수행하는 에이전트에게 그 역할에 한정된 맥락을 축적시킬 때 쓴다.

**현재 이 프로젝트에는 커스텀 서브에이전트 정의가 없다**(`.claude/agents/` 부재). 지금은 기본 제공 에이전트만 사용 중이므로 해당 사항 없음.

## 요약

1. 시작 시 자동으로 들어오는 건 `MEMORY.md` 첫 200줄뿐이다
2. 상세는 주제 파일에 넣고, 인덱스에는 **열어볼지 판단할 단서**를 남긴다
3. 인덱스에 없는 파일은 존재하지 않는 것과 같다 ([[memory-layout]] 참고)
4. `CLAUDE.md`는 전부 로드되지만 짧을수록 잘 지켜진다 — 현재 380줄, 분리 검토 대상
