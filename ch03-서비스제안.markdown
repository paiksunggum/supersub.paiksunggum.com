## 3.1 서비스 개념

**{{ site.report.team }}** 는 사용자가 올린 경기·연습 영상을 분석해 실력과 플레이 특징을
지표로 만들고, 그 지표를 근거로 팀과 용병을 연결하는 플랫폼이다. 한 문장으로 정의하면
다음과 같다.

> 영상을 올리면 자세와 플레이 특징이 분석되고, 그 분석 결과로
> **"이 사람이 우리 팀에 맞는가", "이 팀이 나에게 맞는가"** 를 판단하게 하는 서비스.

기존 매칭 서비스는 실력을 모른 채 사람을 연결하고, 기존 영상 분석 서비스는 분석 결과를
개인 훈련용으로만 쓴다(2.2). 본 서비스는 **분석을 매칭의 입력으로 삼는다는 점**에서
양쪽 어디에도 속하지 않는다.

### 처리 흐름

```
영상 업로드 → 자세·특징 분석 → 분석 리포트(선수 카드)
                                      │
                     팀 요구 조건 ────┼──→ 적합도 산출 → 후보 추천
                                      │
             경기 참여 → 상호 평가 ───┘  (분석 결과 보정)
```

분석은 한 번으로 끝나지 않는다. 영상이 추가될수록 지표가 정밀해지고, 경기 참여 후
상호 평가가 분석 결과를 현실과 대조해 보정한다. **영상 분석이 주 지표이고, 평가와
이력은 보정 수단이다.**

## 3.2 주요 기능

| 코드 | 기능 | 설명 | 대응 과제 |
|---|---|---|---|
| **F-01** | **영상 업로드** | 클립을 업로드한다. 종목·동작을 지정하고 **촬영 가이드에 따라 규격을 안내한다** | P2 |
| **F-01a** | **업로드 사전 검사** | 인물 수·크기·길이·흔들림을 자동 검사해 규격 미달 영상을 업로드 단계에서 걸러낸다 | P2 |
| **F-02** | **자세·특징 분석** | 영상에서 동작 구간을 검출하고 자세 지표와 플레이 특징을 추출한다 | P2 |
| **F-03** | **분석 리포트** | 분석 결과를 지표·요약 문장·대표 장면으로 제시한다(선수 카드) | P3 |
| **F-04** | **적합도 산출** | 팀의 요구 조건 및 기존 구성원 특징과 대조해 적합도를 산출한다 | P4 |
| F-05 | 후보 추천 | 적합도를 근거로 후보를 순위와 사유를 붙여 제시한다 | P1 |
| F-06 | 경기 등록 | 일시·장소·종목·필요 포지션·요구 수준을 등록한다 | P1 |
| F-07 | 지원·수락 | 용병이 지원하거나 팀이 제안한다. 양측 수락 시 확정된다 | P1 |
| F-08 | 프로필 | 분석 지표·대표 영상·참여 이력·활동 조건을 표시한다 | P2 |
| F-09 | 상호 평가 | 경기 종료 후 팀과 용병이 서로를 평가한다. 분석 결과 보정에 쓴다 | P5 |
| F-10 | 팀 관리 | 팀 생성, 구성원 관리, **팀 평균 특징 산출** | P4 |
| F-11 | 알림 | 분석 완료·추천·확정·경기 임박을 알린다 | — |
| F-12 | 신고·제재 | 노쇼·비매너·영상 도용을 신고하고 누적 시 이용을 제한한다 | P5 |
| **F-13** | **선수 카드·호칭** | 분석 지표와 평가를 종합해 **강점 호칭**을 부여하고 카드로 표시한다 | P3 |
| **F-14** | **스쿼드 구성·공유** | 팀 구성원의 카드로 라인업을 구성하고 이미지로 공유한다 | — |
| **F-15** | **평가 신뢰도 관리** | 평가자별 신뢰도를 산출해 가중치에 반영하고 이상 평가를 걸러낸다 | P5 |

**F-01~F-05를 필수 개발 범위**로 한다. 이 다섯 기능이 서비스의 정체성이며, 나머지는
매칭을 성립시키기 위한 지원 기능이다. 세부 요구사항은 5장에서 정의한다.

### 영상 입력 규격

분석 대상은 **경기 전체 영상이 아니라 한 사람이 크게 잡힌 짧은 클립**으로 한정한다.
광각으로 촬영된 경기 영상에서 특정 인물을 추적해 분석하려면 다중 인물 검출·추적·재식별이
필요하고, 인물이 작게 잡히면 자세 추정 정확도가 급격히 떨어진다. 입력을 제한하는 것이
분석 품질을 확보하는 가장 확실한 수단이다.

| 항목 | 기준 | 이유 |
|---|---|---|
| 인물 수 | 분석 대상 **1명**만 프레임에 존재 | 대상 식별 실패를 방지한다 |
| 인물 크기 | 전신이 **프레임 높이의 50% 이상** | 관절 추정 정확도를 확보한다 |
| 촬영 범위 | 머리부터 발끝까지 포함, 잘림 없음 | 하체 지표 산출에 필요하다 |
| 길이 | **5~30초**, 동작 1~5회 반복 | 분석 시간과 비용을 제한한다 |
| 카메라 | **고정 촬영.** 줌·패닝·흔들림 없음 | 좌표 기준점을 유지한다 |
| 촬영 각도 | 종목·동작별 지정 각도 (아래) | 지표마다 필요한 시점이 다르다 |
| 화질 | 720p 이상, 30fps 이상 (60fps 권장) | 빠른 동작의 프레임 누락을 막는다 |
| 조명 | 역광·야간 저조도 회피 | 관절 검출 실패를 줄인다 |

### 종목별 촬영 각도

| 종목 | 동작 | 촬영 위치 |
|---|---|---|
| 야구 | 투구 | 측면 90°. 던지는 팔 반대편 |
| 야구 | 타격 | 정면 또는 측면. 두 각도 모두 있으면 지표가 늘어난다 |
| 풋살 | 슈팅 | 측후면 45°. 디딤발과 임팩트가 함께 보이는 위치 |
| 풋살 | 드리블 | 정면. 방향 전환이 보이는 위치 |

### 규격 미달 처리

규격은 안내에 그치지 않고 **업로드 단계에서 자동 검사한다**(F-01a). 분석 후에 품질
문제를 알리면 연산 비용만 쓰고 사용자 경험도 나빠진다.

| 검사 결과 | 처리 |
|---|---|
| 인물이 2명 이상 검출 | 업로드 반려. 대상 1명만 나오도록 재촬영 안내 |
| 인물 크기·전신 포함 미달 | 업로드 반려. 촬영 거리 조정 안내 |
| 길이 초과·미달 | 구간 지정 요청 또는 반려 |
| 흔들림·저조도 등 경계 사례 | 업로드는 허용하되 **분석 신뢰도를 낮게 표시**한다 |

반려 시에는 어떤 기준에 걸렸는지와 재촬영 방법을 함께 제시한다. 촬영 가이드는 업로드
화면에 **예시 영상과 도식으로 상시 노출**한다.

## 3.3 영상 분석 및 AI 에이전트 적용 방안

### 분석 파이프라인

| 단계 | 처리 | 산출 |
|---|---|---|
| 0. 규격 검사 | 인물 수·크기·길이·흔들림 검사 (F-01a) | 통과 여부, 신뢰도 등급 |
| 1. 전처리 | 해상도·프레임 정규화 | 정규화 영상 |
| 2. 동작 구간 검출 | 종목별 주요 동작 구간을 잘라낸다 | 동작 클립 |
| 3. 자세 추정 | 관절 위치를 프레임 단위로 추정한다 | 관절 좌표 시계열 |
| 4. 지표 산출 | 관절 좌표에서 종목별 자세 지표를 계산한다 | 수치 지표 |
| 5. 특징 요약 | 지표를 종합해 플레이 성향을 문장으로 요약한다 | 선수 카드 |

3~4단계는 **규칙 기반 계산**으로 수행한다. 같은 영상에 대해 항상 같은 결과가 나와야
사용자가 지표를 신뢰할 수 있기 때문이다. AI 에이전트는 5단계와 적합도 설명에 적용한다.

### 종목별 분석 항목

| 종목 | 분석 동작 | 자세 지표 예 | 플레이 특징 예 |
|---|---|---|---|
| **풋살** | 슈팅, 드리블, 패스, 수비 자세 | 디딤발 각도, 상체 기울기, 임팩트 자세, 방향 전환 속도 | 왼발·오른발 선호, 압박 성향, 활동 범위 |
| **야구** | 투구 폼, 타격 폼, 송구, 주루 | 릴리스 포인트, 어깨·골반 회전 순서, 스탠스 폭, 스윙 궤적 | 구속대, 타격 타이밍, 수비 반응 |

야구는 동작이 정지 상태에서 시작해 구간이 명확하므로 자세 지표의 신뢰도가 높다.
풋살은 연속 동작이라 구간 검출이 어려운 대신, 반복 횟수가 많아 통계적 안정성을 얻는다.
**두 종목의 성격 차이를 같은 파이프라인의 파라미터 차이로 흡수한다.**

### AI 에이전트의 역할

| 지점 | 역할 |
|---|---|
| 요청 해석 | "이번 주 토요일 아침 수비 자원, 우리 팀 수준에 맞게"와 같은 자연어 요청을 매칭 조건으로 변환한다 |
| 특징 요약 | 수치 지표를 사람이 읽을 수 있는 플레이 성향 설명으로 바꾼다 |
| 적합도 설명 | 후보를 추천한 근거를 팀의 조건과 대조해 문장으로 제시한다 |

> 예: "오른발 슈팅 임팩트 자세가 안정적이고 방향 전환이 빠릅니다. 최근 분석 영상 4건,
> 압박 성향이 높아 수비형 미드필더를 찾는 팀 요구와 부합합니다. 팀 평균보다
> 활동량 지표가 높습니다."

### 적용 원칙

- 에이전트는 **추천과 설명까지만** 수행한다. 매칭 확정은 반드시 사람의 수락을 거친다.
- 실력 지표 산출은 규칙 기반 계산으로 하고, 에이전트가 수치를 조정하지 않는다.
- 분석 근거가 된 지표와 장면은 사용자가 리포트에서 직접 확인할 수 있어야 한다.
- 분석 결과를 **부상 위험·의학적 소견으로 제시하지 않는다.**

세부 모델 구성과 처리 흐름 설계는 6.3에서 기술한다.

> 확인 필요 — 자세 추정 모델 선정, 영상 처리 인프라, 분석 소요 시간 목표는 6장·7장에서
> 확정한다.

## 3.4 실력 검증 및 적합도 판단

### 검증 구조

| 요소 | 성격 | 설명 |
|---|---|---|
| **영상 분석** | 주 지표 | 자세 지표와 플레이 특징. 관찰 가능한 근거이며 재현 가능하다 |
| 상호 평가 | 보정 | 경기 후 평가로 분석 결과와 실제 경기력의 차이를 보정한다 |
| 참여 이력 | 보정 | 참여 횟수·노쇼율·최근 활동성으로 신뢰도를 조정한다 |
| 자기 신고 | 초기값 | 영상 분석 전 임시 기준점. 분석이 누적되면 영향이 소멸한다 |

영상 분석을 주 지표로 두는 이유는 **검증 가능하기 때문**이다. 상호 평가는 평가자의
주관과 관계에 좌우되지만, 자세 지표는 같은 영상에서 같은 값이 나오며 근거 장면을 함께
제시할 수 있다.

### 표시 방식

실력은 단일 등급 하나로 환원하지 않고 **지표 묶음(선수 카드)으로 표시**한다. 생활체육
용병 매칭에서 필요한 판단은 "누가 더 잘하는가"가 아니라 **"우리에게 맞는가"**이기
때문이다. 수비가 필요한 팀에게 공격 지표가 높은 후보는 상위 등급이어도 적합하지 않다.

- 종합 수준: 5단계 (입문 / 초급 / 중급 / 상급 / 최상급)
- 특징 지표: 종목별 4~6개 항목을 개별 표시
- **분석 표본이 부족하면 "분석 중"으로 표시**하고 확정 지표를 제시하지 않는다

### 설계 원칙 — 서열이 아니라 적합

본 서비스는 **전체 순위표를 두지 않는다.** 능력치와 등급은 사용자 간 서열을 매기는
값이 아니라, 본인의 특징을 설명하고 팀과의 적합을 판단하는 값이다.

| 근거 | 내용 |
|---|---|
| 판단 기준과 일치 | 매칭에서 필요한 답은 "누가 더 잘하는가"가 아니라 **"우리에게 맞는가"**다. 순위는 이 질문에 답하지 못한다 |
| 참여 위축 방지 | 생활체육 참여자에게 공개 서열은 위화감을 만든다. 하위 사용자가 이탈하면 매칭 풀 자체가 줄어든다 |
| 지표 왜곡 방지 | 순위가 목적이 되면 점수가 잘 나오는 영상만 올리게 된다. 3.4의 누적 분석 원칙이 무너진다 |

이 원칙은 다음 형태로 구체화한다.

- 전체·지역 랭킹 화면을 만들지 않는다.
- 능력치는 **본인 이력 대비 변화**로 보여 준다. 타 사용자와의 비교로 제시하지 않는다.
- 비교가 필요한 경우는 **팀 평균과의 대조**에 한정한다. 적합도 판단에 필요한 범위다.

### 적합도 산출

적합도는 다음 세 축을 종합한다.

| 축 | 대조 대상 | 예 |
|---|---|---|
| 수준 적합 | 팀 평균 수준 | 등급 차 1단계 이내 |
| 역할 적합 | 팀이 요청한 포지션·역할 | 수비형 요청 ↔ 압박 성향 지표 |
| 성향 적합 | 팀 구성원의 평균 특징 | 팀 활동량·플레이 속도와의 간극 |

적합도는 점수만 제시하지 않고 **어느 축에서 맞고 어긋나는지를 함께 표시**한다.

### 한계와 대응

| 한계 | 대응 |
|---|---|
| 영상 촬영 조건이 제각각이다 | **입력 규격을 정하고 업로드 단계에서 자동 검사한다**(3.2). 경계 사례만 신뢰도를 낮춰 표시한다 |
| 규격을 지킨 촬영이 번거롭다 | 촬영 가이드를 업로드 화면에 도식으로 상시 노출한다. 규격 자체를 **삼각대 없이 거치 후 5~30초 촬영** 수준으로 낮게 유지한다 |
| 타인의 영상을 올릴 수 있다 | 본인 확인 절차와 신고 기능(F-12)을 둔다. 경기 후 평가와 지표가 크게 어긋나면 재검증 대상으로 표시한다 |
| 잘된 장면만 골라 올릴 수 있다 | 단일 클립이 아닌 **누적 분석**을 기준으로 지표를 산출한다 |
| 자세가 좋아도 경기력은 다를 수 있다 | 상호 평가로 보정하고, 분석 지표를 경기력 예측이 아닌 **특징 설명**으로 제시한다 |

마지막 항목은 서비스 신뢰와 직결된다. **분석 결과를 실력의 확정 판정으로 제시하지
않고, 판단을 돕는 근거로 제시한다는 원칙을 화면 문구 수준까지 일관되게 적용한다.**

## 3.5 선수 카드와 호칭

### 도입 목적

분석 리포트는 정확하지만 **다시 열어 볼 이유가 없다.** 한 번 읽고 나면 사용자가
서비스에 머물 동기가 사라지고, 경기 후 상호 평가(F-09)도 하지 않는다. 평가가 모이지
않으면 3.4의 보정 체계 자체가 작동하지 않는다.

선수 카드는 이 문제를 푸는 장치다. 목적은 세 가지다.

| 목적 | 내용 |
|---|---|
| **평가 참여 유인** | 평가가 쌓여야 호칭이 부여된다. 평가할 이유를 만든다 |
| **재방문 유인** | 영상을 더 올리고 경기에 더 참여할수록 호칭이 늘어난다 |
| **확산 경로** | 카드 이미지를 외부에 공유한다. 광고비 없이 유입을 만든다 |

### 수치 능력치를 두지 않는 이유

카드에는 **숫자로 된 능력치를 표시하지 않는다.** 수치는 그 자체로 정렬 가능한 값이라,
순위표를 만들지 않아도 사용자가 스스로 서열을 만든다. 캡처를 모아 비교하거나 커뮤니티에
줄을 세우는 방식으로 3.4의 원칙이 우회된다.

대신 **강점을 호칭으로 표현한다.** 호칭은 상대 비교가 아니라 **절대 기준 충족 여부**로
부여되므로 서열이 되지 않는다. 두 사람이 같은 호칭을 함께 가질 수 있고, 호칭이 다르면
우열이 아니라 성향이 다른 것으로 읽힌다.

| 구분 | 표시 위치 | 성격 |
|---|---|---|
| **호칭** | 선수 카드 (공개·공유) | 강점 요약. 서열이 되지 않는다 |
| **수치 지표** | 분석 리포트 (매칭 판단용) | 근거. 팀 요구 조건과의 대조에 사용한다 |

수치를 없애는 것이 아니라 **공개되는 면에서 내린다.** 매칭 판단은 여전히 리포트의
지표를 근거로 한다(3.3).

### 호칭의 세 종류

| 종류 | 근거 | 예 |
|---|---|---|
| **강점 호칭** | 영상 분석 지표가 기준을 충족 | 안정된 임팩트, 빠른 방향 전환, 일정한 릴리스 |
| **활동 호칭** | 참여 이력·출결 기록 | 개근, 정시 참석, 꾸준한 기록 |
| **용병 호칭** | **용병으로 참여한 경기에서 받은 평가** | 다시 부르고 싶은 선수, 첫 경기부터 어울린 선수 |

세 번째가 본 서비스의 핵심이다. 용병 참여 후 팀이 남긴 평가가 좋으면 그 결과가 호칭으로
남아, **다음 매칭에서 근거로 쓰인다.** 2장에서 정의한 이력 부재 문제가 여기서 해소된다.
용병 호칭은 여러 팀에서 반복 확인될수록 강화된다.

### 종목별 강점 호칭 예시

| 종목 | 호칭 | 부여 근거 |
|---|---|---|
| 풋살 | 안정된 임팩트 | 슈팅 시 디딤발·상체 각도의 편차가 기준 이하 |
| 풋살 | 빠른 방향 전환 | 방향 전환 구간의 소요 시간이 기준 이하 |
| 풋살 | 양발 사용 | 좌우 발 사용 비율이 기준 범위 내 |
| 야구 | 일정한 릴리스 | 투구 간 릴리스 포인트 편차가 기준 이하 |
| 야구 | 순서가 맞는 회전 | 어깨·골반 회전 순서가 기준에 부합 |
| 야구 | 짧은 스윙 궤적 | 스윙 궤적 길이가 기준 이하 |

> 확인 필요 — 각 호칭의 구체적 임계값은 6장 설계 단계에서 실제 분석 데이터를 보고
> 정한다. 현재는 호칭 체계의 구조만 정의한다.

### 부여 규칙

| 규칙 | 내용 |
|---|---|
| 절대 기준 | 다른 사용자와 비교하지 않는다. 본인의 지표가 기준을 충족하면 부여한다 |
| 표본 요건 | 분석·평가 표본이 일정 수 이상일 때만 부여한다. 미달 시 "확인 중"으로 표시한다 |
| 최근성 | 최근 활동 기준으로 산정한다. 오래된 기록만으로 유지되지 않는다 |
| **미부여 방식** | 기준에 미달하면 **호칭이 붙지 않을 뿐, 부정적 표식을 붙이지 않는다** |
| 개수 비교 없음 | 호칭 보유 개수로 사용자를 정렬하거나 순위를 매기지 않는다 |

네 번째가 중요하다. 부정 평가의 효과를 **"호칭 미부여"로 한정**하면, 악의적 평가
하나가 기존 평판을 훼손할 수 없다(3.4 피해 상한 설계). 제재는 평가가 아니라 신고·노쇼
기록으로 처리한다(F-12).

### 카드 구성

| 요소 | 내용 |
|---|---|
| 종합 수준 | 5단계 등급(3.4). 적합도의 수준 축 판단에 필요한 최소 정보 |
| 호칭 | 강점·활동·용병 호칭 |
| 포지션 | 주 포지션 표기 |
| 대표 장면 | 분석 영상의 대표 프레임 |
| 활동 요약 | 최근 참여 횟수 등 사실 정보 |

### 스쿼드

팀은 구성원의 카드로 라인업을 구성하고 이미지로 공유한다. 개인 단위 확산이 팀 단위
확산으로 이어지는 경로이며, 팀이 자기 전력을 한눈에 보게 되므로 **어느 자리에 용병이
필요한지 인지하게 만드는 효과**가 있다. 구인 수요를 서비스 안에서 발생시킨다.

### 두 개의 화면을 분리한다

| 화면 | 성격 | 용도 |
|---|---|---|
| 선수 카드 | 호칭·요약 | 재미, 공유, 성장 확인 |
| 분석 리포트 | 지표·근거 장면 | 매칭 판단, 적합도 검토 |

**매칭 판단은 리포트를 근거로 한다.** 호칭만으로 추천 순위를 정하면 3.3에서 세운
"근거를 제시한다"는 원칙이 무너진다. 카드는 리포트로 들어가는 입구 역할을 한다.

### 주의 사항

- 기존 스포츠 게임의 **카드 디자인·능력치 약어·등급 명칭을 그대로 차용하지 않는다.**
  독자적인 시각 요소와 용어를 사용한다.
- 실존 선수의 이름·사진을 예시로 사용하지 않는다.
- 카드는 수집·경쟁 요소를 강화하는 방향으로 확장하지 않는다. **전체 순위표를 두지
  않는다는 원칙(3.4)** 은 카드에도 동일하게 적용한다. 카드 간 비교·대결 기능을
  추가하면 호칭이 서열 경쟁의 도구가 된다.
- 호칭 문구는 **부정형을 쓰지 않는다.** 약점은 본인만 보는 분석 리포트에서 다룬다.
